# EnergyTool

ИИ-консультант для сайта МТС EnergyTool. Помогает клиенту разобраться в учёте электроэнергии, расходах и потерях, а менеджеру — получить обращение с понятной задачей.

## Что есть в приложении

- **Консультация без обязательной заявки.** Можно задавать вопросы, дополнять задачу и возвращаться к сохранённым разговорам.
- **Источники ответа.** В режиме отладки доступны документы, время ответа и статус обработки.
- **Обращение во время ожидания.** Если генерация затянулась, клиент может оставить заявку оператору вместе с контекстом.
- **Очередь менеджера.** Карточки, правки, статусы обработки, причины решений и выгрузка TXT/JSON.
- **Ответы специалистов.** Вопросы без подтверждённого ответа в базе передаются человеку. Его ответ сохраняется в беседе.
- **Проверенные знания.** Специалист готовит материал, редактор проверяет его. Одобренные записи становятся доступны поиску; отозванные исключаются.

## Под капотом

```text
Браузер → Go API → Python-агент → Ollama / Qwen3.8-27B
              │          ↑
       История и заявки   База EnergyTool + проверенные знания
```

Фронтенд написан на HTML, CSS и JavaScript. Главная страница использует сохранённую React-витрину EnergyTool. Go отвечает за сессии, заявки и работу сотрудников. Python собирает контекст и обращается к модели через OpenAI-совместимый API.

Поиск объединяет BM25 и символьные n-граммы, затем дополняет найденные материалы условиями применения продуктов. История и рабочие данные хранятся в JSON, проверенные знания передаются агенту через отдельный Docker-том.

```text
frontend/      страницы, стили, JavaScript и веб-прокси
backend/       Go API и хранение данных
agent/         поиск, промпты и логика консультанта
compose.yaml   запуск трёх сервисов
.env.example   настройки окружения
```

## Запустить у себя

По умолчанию используется локальная **Qwen3.8-27B через Ollama**, тег `qwen3.8:27b`. Веса модели занимают около 18 ГБ на диске; скорость и возможность запуска зависят от доступной памяти и оборудования. [Модель в каталоге Ollama](https://ollama.com/library/qwen3.8:27b)

**1. Подготовить модель.** Установите и откройте Ollama на компьютере, затем загрузите модель.

```bash
ollama pull qwen3.8:27b
```

**2. Подготовить проект.** Скопируйте настройки и поместите базу знаний организаторов в `data/knowledge-base.zip`. База поставляется отдельно.

```bash
cp .env.example .env
```

В примере уже указаны `LLM_MODEL=qwen3.8:27b` и адрес Ollama на хосте для Docker Desktop.

**3. Запустить сервисы.** Нужен работающий Docker с Compose.

```bash
docker compose up --build -d
```

После запуска введите в адресной строке браузера `http://localhost:8768` и откройте консультацию с главной страницы. Адрес ведёт на приложение на вашем компьютере и доступен, пока сервисы запущены.

Рабочие места менеджера и специалиста открываются по путям `/applications.html` и `/specialist.html` на том же адресе. На странице специалиста нужны идентификатор сотрудника, роль и ключ из `OPERATOR_TOKEN`.

Для загрузки весов и первой сборки Docker нужен интернет. После подготовки генерация через Ollama выполняется локально. Внешние элементы референсного сайта могут обращаться к интернету.

## Настройки и управление

Основные параметры находятся в `.env`.

| Параметр | Для чего |
|---|---|
| `LLM_MODEL` | Модель Ollama, по умолчанию `qwen3.8:27b` |
| `LLM_BASE_URL` | Адрес модели, в Docker Desktop — `http://host.docker.internal:11434/v1` |
| `LLM_API_KEY` | Для локальной Ollama используется значение `local-ollama` |
| `WEB_PORT` | Порт приложения, по умолчанию `8768` |
| `OPERATOR_TOKEN` | Ключ сотрудников, в локальном примере — `local-demo-operator` |
| `MAX_TOKENS` | Лимит токенов ответа |
| `CONTEXT_CHARS`, `TOP_K` | Объём контекста базы и число основных фрагментов поиска |
| `LLM_TIMEOUT`, `LLM_ATTEMPTS` | Тайм-аут и число транспортных попыток |
| `MAX_WORKERS` | Число параллельных запросов к модели |

Можно подключить другую модель через `LLM_MODEL` или другой OpenAI-совместимый сервер через `LLM_BASE_URL` и `LLM_API_KEY`.

Посмотреть логи или остановить приложение

```bash
docker compose logs --tail=50
docker compose down
```

Обычная остановка сохраняет данные. `docker compose down -v` удаляет Docker-тома с историей, заявками и проверенными знаниями.
